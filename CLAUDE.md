# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A personal collection of standalone [Processing](https://processing.org/) generative-art
sketches, in three different toolchains. There is no shared build system, package
manager, linter, or test suite — each subdirectory is an independent sketch that
runs (or is opened) on its own.

## Sketch types and how to run them

- **p5.js sketches** (`*_js/` directories, e.g. `circles_js`, `rect_js`, `shapes_js`,
  `shapes_animated_js`, `pixel_painting`): plain `index.html` + `sketch.js`/`mySketch.js`
  loading a vendored `p5.js` (and sometimes `p5.sound.min.js`) via `<script>` tags. Run by
  opening `index.html` in a browser — no build step. Sketches follow the p5.js
  `setup()`/`draw()` convention; static-image sketches leave `draw()` empty and do all
  the work in `setup()`.
- **Processing Java sketches** (`shapes/`, `shapes_colour/`): `.pde` files meant to be
  opened in the Processing IDE (or run via `processing-java`). `setup()` computes and
  typically calls `save("path.png")` once; there's no `draw()` loop.
- **Processing Python (`.pyde`) sketches** (`python/random/`, `python/truchet_tiles/*/`):
  legacy Processing "Python mode" sketches — top-level procedural code, not `py5`. Each
  variant lives in its own directory alongside a generated `output.png` and a
  `sketch.properties` (`mode=Python`, always the same boilerplate). These are opened in
  the Processing IDE with Python mode installed; they are not run with plain `python3`.
- **py5 sketches** run headless via `py5-docker/`: this is a generic Docker runner, not
  tied to a specific sketch. Build once with `docker build -t py5-sketch py5-docker/`,
  then run against any directory of `.py` files with
  `docker run --rm -v "$(pwd)/<dir>:/app" py5-sketch`. By default it runs every `.py`
  file directly under the mounted directory (alphabetical, one Xvfb instance each);
  pass a filename argument or set `SKETCH=<file>.py` to run just one. Sketches must call
  `py5.save(...)` themselves to produce output, and each sketch should save to a
  distinct filename if sharing a mounted directory. See `py5-docker/README.md` for full
  details and `py5-docker/example_sketch.py` for the expected shape of a sketch
  (`import py5`, define `setup()`, end with `py5.run_sketch()`).

## Conventions

- Each sketch directory that's worth describing has its own `README.md` with a short
  description, an example image, and (for p5.js sketches originally built in the online
  editor) links to the p5 web editor. The root `README.md` is a flat index linking to
  every sketch directory — add new sketches there too.
- Output images are typically checked in next to the sketch that produced them
  (`Example/*.png`, `output.png`, `example.png`), generated by the sketch's own
  `save`/`saveFrame`/`py5.save` call rather than committed by hand.
- No shared dependency management: p5.js/p5.sound.min.js are vendored directly in each
  `*_js/` directory rather than fetched from a CDN or npm.
